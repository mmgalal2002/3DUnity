## Controls

1. Load a PNG/JPEG through **Floor plan**, then open **Calibrate / color rules** below the guide dimensions.
2. In **Calibration**, choose **Two points**, pick A and B on the original image and enter the measured distance in metres. Alternatively enter explicit **m/px**, **mm/px** or **px/m**. **Confirm uniform scale + save settings** sets both guide dimensions together and records confirmation; it does not resize the room or existing objects.
3. In **Color rules**, add or duplicate categories, sample source-image colors and choose RGB or HSV matching and tolerance. Categories are Wall, Opening, Reference and Ignore. Choose a physical material explicitly; image and display colors do not imply a shielding material. Height, base elevation, thickness and minimum future path length are stored for the subsequent generator.
4. **Preview color mask** processes original-resolution pixels in small slices. Inspect the combined or individual category masks and their counts. **Cancel processing**, settings changes or history changes invalidate pending work. Empty/failed/canceled processing keeps the previous mask and never changes scene objects.
5. **Apply settings** commits metadata in one undo step. **Close / discard unapplied edits** or Escape discards draft changes. The two content panes scroll independently so status messages cannot hide Apply/Close.
6. In the main **Floor plan** panel, select an existing generation batch to regenerate or **New batch**. **Auto-connect walls**, the connection tolerance (default 0.02 m), and cross-category permission are separate from grid and wall snapping. Generate, inspect the path/junction and 3D previews, optionally correct endpoints/categories or split/merge/delete paths, then **Apply connected walls** or **Cancel / clear preview**. Apply uses the staged geometry; Cancel does not delete committed walls. A new batch with identical source/settings is rejected rather than duplicated.

The preview supports fit/reset, zoom and right-drag pan. These only affect the display. A retained mask is labelled stale when its source/settings/history no longer match. Both snap assists remain independent of calibration.

## Coordinates, matching and limits

- Source coordinates describe the decoded image's original pixel edges, with the top-left pixel centre at `(0.5, 0.5)`. Picking and conversion use these coordinates, not preview pixels. Image X maps to Unity X; downward image Y maps to decreasing Unity Z before guide rotation. Unity Y is elevation. Guide translation/rotation apply once.
- `metresPerPixel = measuredMetres / pixelDistance`. A 500-pixel span over 5 metres gives 0.01 m/px; 100 pixels then span 1 metre. Manual units convert to the same internal scale. Coincident points and invalid/nonfinite/out-of-range values are rejected without partially resizing the guide.
- Confirmation requires a uniform extent. Editing width/height independently makes calibration stale when either ratio differs from the confirmed value. Wall generation requires current confirmation; color-mask previews can run before confirmation.
- RGB distance is normalized RMS over decoded sRGB channels. HSV uses circular hue distance, doubled to a 0–1 range, with saturation/value in the same RMS formula. Tolerance is 0–1. Fully transparent pixels are always excluded; a configurable minimum alpha excludes additional pixels.
- Lower priority numbers win. Equal priorities sort by stable ordinal rule ID, independent of list order. Every pixel has at most one owner; overlapping candidate matches are counted. Ignore/opening/reference owners remain separate from wall categories.
- Eight-connected component filtering removes regions below each rule's minimum area. It preserves a connected diagonal. Minimum path length affects extracted centerlines, not color masks. Bounded same-rule thinning avoids generating both edges of a thick stroke; unsupported filled/complex strokes produce diagnostics.
- Mask processing accepts at most **4,194,304 original pixels**, **8192 pixels per side**, and **32 rules**. The existing tracing guide retains its 16 MP image limit. The processing limit is checked before `GetPixels32`; the mask worker has bounded arrays and advances in 4096-work-unit slices. Display masks are at most 1024 pixels per side. Texture pixels are copied once per active source, not every frame.

## Persistence and calculation boundary

Optional native `floorPlan.authoring` version-1 metadata stores a stable authoring ID, SHA-256 of the embedded source bytes, source dimensions, calibration and rules. Existing native v1/v2 and guide-free designs still load. C# validates the fingerprint against the embedded source when importing/applying. The JavaScript bridge validates metadata structure and retains unknown extensions; the actual image-byte fingerprint check occurs in Unity.

Native saves embed the image and metadata. Canonical export retains them under `room.floorPlan` as editor metadata; QA and shielding geometry ignore them. A color-only edit cannot change material, item counts or dose. Standalone **RoomStudio.FloorPlan v1** export remains the existing image/vector guide schema and intentionally omits authoring metadata; the UI explains this distinction.

Generation reuses `PlanAuthoring.PixelToWorld`, requires `CalibrationCurrent`, and validates each wall rule's explicit material and linked-ceiling compatibility through `RequireWallRule`. Optional native version-2 batches retain a portable source snapshot, original/corrected paths, item references, rule properties, manual/deleted overrides and connection settings. Regeneration is scoped to the selected batch and previews conflicts instead of overwriting manual work. Missing connection settings retain auto-connect on, cross-category off and 0.02 m tolerance.

Straight generated walls can retain provenance under canonical `room.floorPlan` editor metadata without changing QA. Joined/clipped geometry explicitly rejects reference QA/canonical export with affected wall IDs; native project JSON is the full editable interchange. Removing the active guide does not erase batch snapshots, but canonical export then rejects the missing metadata boundary.
